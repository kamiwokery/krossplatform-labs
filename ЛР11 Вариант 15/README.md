## Контрольные вопросы (ответы)

1. **Что такое полиморфизм в Java?** Способность объектов с разной реализацией иметь общий интерфейс: один и тот же код работает с объектами разных классов, вызывая их собственные версии методов.
2. **Разница статического и динамического полиморфизма?** Статический — перегрузка, решается на этапе компиляции (одинаковые имена, разные параметры). Динамический — переопределение, решается во время выполнения по реальному типу объекта (одинаковые имя и параметры).
3. **Что такое перегрузка методов?** Несколько методов с одинаковым именем в одном классе, различающихся параметрами (количество, тип, порядок). Различие только в типе возврата или только в именах параметров — НЕ перегрузка.
4. **Что такое переопределение?** Метод дочернего класса с тем же именем, параметрами и совместимым типом возврата, что и у родительского. Доступ не строже родительского, используется `@Override`.
5. **Как отличить перегрузку от переопределения?** Перегрузка — разные параметры, один класс, выбор версии при компиляции. Переопределение — одинаковые параметры, родитель и потомок, выбор выполняется в runtime.
6. **Какой тип полиморфизма использует `@Override`?** Динамический (переопределение, Overriding).
7. **Можно ли перегрузить статические методы?** Да — статические методы можно перегружать (по параметрам).
8. **Можно ли переопределить статические методы?** Нет — можно только «скрыть» (объявить свой с тем же именем); это не переопределение. Также нельзя переопределить `private` и `final` методы.
9. **Зачем нужен `instanceof`?** Проверить, является ли объект экземпляром класса (или реализует интерфейс) — для безопасного нисходящего преобразования `(Child) obj` без `ClassCastException`.

## Теория в коде

- `cook()`, `cook(int)`, `cook(String)` — статический полиморфизм (перегрузка), выбор версии компилятором.
- `@Override getTaste()` в `Pizza`/`Soup` — динамический полиморфизм (переопределение), вызов через `Food[]` в runtime.
- `addTopping(...)`, `stir(...)` — собственная перегрузка в производных классах.
